# RCA — Deploy run 3ad15849-fc57-4f4b-b701-379e6153fdea (campaign-companion-13)

## Symptom
Redeploy failed at `build_image`, EAS lane (`eas-update`, Cloud Build step #7). Docker backend build was fine; the OTA publish aborted.

## Exact error (Cloud Build step #7 "eas-update")
```
✖ Failed to publish updates
Manifest Validation Error:
scheme:'scheme' must match pattern "^[a-z][a-z0-9+.-]*$"
scheme:must be array
scheme:must match exactly one schema in oneOf
This is likely a problem with your app.json, or app.config.js
Request ID: 093da9ed-a923-4bd2-a2e0-be156160486c
    Error: GraphQL request failed.
```

## Root cause (confirmed from source in eph pod)
`frontend/app.json` sets:
```json
"scheme": "AOBLRS"
```
Expo requires the URL `scheme` to be a **lowercase** string matching `^[a-z][a-z0-9+.-]*$` (or an array of such strings). `"AOBLRS"` is uppercase, so it satisfies neither branch of the `oneOf`, and `eas update` rejects the manifest during publish.

There is **no** `app.config.js` in the frontend — `app.json` is the sole config source, so the fix must be made there.

## Fix (Source — EAS OTA update)
In `frontend/app.json`, lowercase the `scheme` value:
```json
"scheme": "aoblrs"
```
(Any all-lowercase value matching the pattern works, e.g. `aoblrs`. Keep it consistent if the scheme is referenced elsewhere for deep-linking.)

## Verification note
Root cause is confirmed by direct inspection of `frontend/app.json` against the exact validation error. The actual `eas update` publish cannot be re-run in the eph sandbox (no Expo credentials there), so the publish itself was not re-executed — but the manifest-validation rule is unambiguous and lowercasing the scheme resolves it.

## Next step for E1
Apply the one-line change to `frontend/app.json`, then re-trigger the deploy.
