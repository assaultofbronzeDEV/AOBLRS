# RCA — Redeploy failed at `pull_source` (campaign-companion-13)

## Summary
Two consecutive redeploy attempts failed at the **`pull_source`** step, before any build/Cloud Build ran. Cause: the file **`backend/.env` is missing from the current preview environment**. The deployer's `pull_source` step reads `backend/.env` while preparing the build context; when it's absent the step aborts.

## Failed runs
- `62e61f31-fb36-4300-9fbd-cb3bb35ae0c3` (original trigger) — failed `pull_source`
- `928e5c09-e68d-4b5f-83dd-64fcefc27742` (my fresh re-pull retry) — failed `pull_source`, identical error

## Exact error
```
pull_source: prepare build context: read envs: read env file backend/.env:
open /tmp/agent-env-.../app/backend/.env: no such file or directory (PathError)
```
The underlying error is flagged `retryable:true`, but a fresh re-pull (`force_repull=true`) reproduced it identically — so it is NOT a transient blip; the file genuinely does not exist in preview.

## Evidence
- Retried once via `resume_pipeline` (fresh re-pull) → same `pull_source` / missing `backend/.env` failure.
- Inspected the source of the **last successful run** `71cd88d9-cb13-47e2-aac0-a152c23397de` in an eph sandbox: `backend/.env` was present (61 bytes) alongside `server.py`, `requirements.txt`. So the file existed at last good deploy and has since gone missing from the preview environment.
- The failed run produced no source archive (`pull_source` aborted first), so the failing run itself could not be sandboxed — diagnosis is from the deployer error + the last-good source comparison.

## Root cause
`backend/.env` was deleted/is absent in the preview pod. `pull_source` requires it to assemble the deploy env context, so every deploy now fails at that step regardless of retries.

## Fix (E1 — Source, Backend)
1. Recreate `backend/.env` in the preview environment (`/app/backend/.env`). It only needs to exist and be readable; at minimum restore the keys the app expects (e.g. `MONGO_URL`, `DB_NAME` — mirror what the last working deploy had; the last-good file was ~61 bytes, so likely just `MONGO_URL` + `DB_NAME`).
2. Re-trigger the deploy.

No manifest change and no platform action is required — this is purely a missing source file in the preview environment.
