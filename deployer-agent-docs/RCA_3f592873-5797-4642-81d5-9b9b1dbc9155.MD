# RCA — Deploy run 3f592873-5797-4642-81d5-9b9b1dbc9155 (campaign-companion-13)

## Symptom
Deploy fails at `build_image`, in the **EAS OTA update lane** (`eas-update`, Cloud Build step #7). Docker backend build is unaffected. Same failure occurred on two consecutive runs (3f592873… and 3ad15849…).

## Error (verbatim, from Cloud Build step #7 "eas-update")
```
✖ Failed to publish updates
Manifest Validation Error:
scheme:'scheme' must match pattern "^[a-z][a-z0-9+.-]*$"
scheme:must be array
scheme:must match exactly one schema in oneOf
This is likely a problem with your app.json, or app.config.js
```
The JS bundle uploaded fine — publish was rejected server-side by Expo's manifest validation.

## Root cause (verified in eph sandbox)
`frontend/app.json` sets:
```json
"scheme": "AOBLRS"
```
Expo requires the URL scheme to match `^[a-z][a-z0-9+.-]*$` (must start with a lowercase letter, lowercase only). `AOBLRS` is uppercase and fails the pattern. There is no `app.config.js` in the source — `app.json` is the sole config, so nothing overrides this value.

Regex check run in-pod:
```
AOBLRS  -> false
aoblrs  -> true
```

Note: this value is user-controlled source and is NOT normalized by the deployer's app.json fix step (that step forces `slug`, background and jsEngine, but leaves `scheme` as-is), so the fix must be made in the source.

## Fix (Source — frontend, one line)
In `frontend/app.json`, change the `scheme` to an all-lowercase value, e.g.:
```json
"scheme": "aoblrs"
```
(any string matching `^[a-z][a-z0-9+.-]*$` is valid). Then re-trigger the deploy.

## Scope / verification
- Verified: the offending value and that the corrected value passes Expo's pattern.
- Not verified end-to-end: `eas update` cannot be run in the sandbox (no Expo token / no secrets). The manifest-validation rule is deterministic, so the lowercase change resolves the rejection.
